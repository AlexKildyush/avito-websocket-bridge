# Avito WebSocket Bridge

Nest.js-приложение, которое открывает Личный кабинет Авито через Puppeteer, отслеживает новые сообщения от указанного контакта и отправляет их на фронтенд в реальном времени через WebSocket.

## Что внутри

- `Nest.js` как основной backend.
- `Puppeteer` для запуска браузера и работы с веб-интерфейсом Авито.
- `Socket.IO` для доставки событий на клиент.
- Статическая HTML-страница для демонстрации.
- Поддержка сохранения браузерной сессии в `AVITO_USER_DATA_DIR`.

## Архитектура

- `src/avito/avito-bridge.service.ts`:
  запускает браузер, проверяет авторизацию, открывает чат с нужным контактом и периодически читает новые сообщения.
- `src/messages/messages.gateway.ts`:
  держит WebSocket-соединения и рассылает события `message` и `status`.
- `src/app.controller.ts`:
  предоставляет `GET /api/health` для быстрой проверки состояния сервиса.
- `public/index.html` и `public/app.js`:
  показывают статусы и поток входящих сообщений.

## Ограничения и практический подход к авторизации

Авито может менять DOM, капчу, антибот-проверки и сценарий входа. Поэтому в проекте заложены два режима:

1. Автоматическая попытка входа по `AVITO_LOGIN` и `AVITO_PASSWORD`.
2. Более надежный режим через сохраненный профиль Chromium в `AVITO_USER_DATA_DIR`.

Для демонстрации и стабильной работы рекомендуется первый запуск делать в не-headless режиме:

1. Запустите сервис.
2. Если статус стал `needs-auth`, выполните вход в открывшемся окне браузера вручную.
3. После успешного входа профиль сохранится в `.avito-session`, и следующие запуски смогут использовать уже активную сессию.

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните значения:

```env
PORT=3000
TARGET_CONTACTS=Рушан Натфуллин,Рушан
AVITO_BASE_URL=https://www.avito.ru
AVITO_MESSAGES_URL=https://www.avito.ru/profile/messenger
AVITO_LOGIN=
AVITO_PASSWORD=
AVITO_USER_DATA_DIR=.avito-session
PUPPETEER_HEADLESS=false
PUPPETEER_SLOW_MO=0
PUPPETEER_TIMEOUT_MS=30000
CLOUDFLARED_PUBLIC_URL=
```

## Локальный запуск

```bash
npm install
npm run start:dev
```

После запуска:

1. Откройте `http://localhost:3000`.
2. Проверьте `http://localhost:3000/api/health`.
3. Если открылось окно Chromium и требуется логин, авторизуйтесь в Авито.
4. Убедитесь, что чат с `Рушан` найден автоматически.

## Настройка Cloudflared

Пример для локального проброса порта `3000`:

```bash
cloudflared tunnel --url http://localhost:3000
```

После запуска `cloudflared` выдаст публичный URL вида:

```text
https://random-name.trycloudflare.com
```

Добавьте этот адрес в `.env` как `CLOUDFLARED_PUBLIC_URL`, чтобы он отображался в статусе сервиса.

Если туннель оборвётся, клиентская страница перестанет получать обновления. Рекомендуется запускать `cloudflared` отдельно под `pm2`, `systemd` или Docker Compose.

## Docker

Сборка:

```bash
docker build -t avito-websocket-bridge .
```

Запуск:

```bash
docker run --rm -p 3000:3000 --env-file .env avito-websocket-bridge
```

Если хотите сохранить браузерную сессию между перезапусками контейнера, примонтируйте том с директорией профиля Chromium.

## Что может потребовать доработки под реальный аккаунт

- CSS-селекторы Авито могут отличаться от текущих предположений.
- Поток сообщений сейчас читается из DOM чата, поэтому при изменении верстки понадобится обновить селекторы.
- Если включена капча или 2FA, полностью безручной вход может быть недоступен.

## Что предоставить для сдачи

- Публичную ссылку от `cloudflared` после реального запуска на вашей машине.
- Заполненный `.env` без коммита секретов.
- Скриншот или короткое видео, где видно входящее сообщение и обновление страницы.
